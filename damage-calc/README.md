# グラブル ダメージ計算機（ベータ）

編成画面・武器タブの「発動中の武器スキル」パネルのスクショを貼ると、バフ・敵防御・減衰・連撃まで含めたダメージ期待値を出すブラウザアプリです。武器やキャラのデータベースは持たず、グリッドの合計値はゲームが表示した値をそのまま使います。

- **非公式のファンツールです。** ゲーム本体（クライアント・通信）には一切触れません。扱うのはユーザーが自分で撮ったスクショだけです。
- **スクショは外部に送信しません。** 文字認識（OCR）はブラウザ内の Web Worker で行います。初回だけ認識エンジンと言語データ（jpn / eng、合わせて数MB）を CDN（jsDelivr）から読み込み、以後はブラウザにキャッシュされます。
- ゲームの画像素材（武器・スキルアイコン等）は同梱していません。

公開場所: サイトの `damage/`（このディレクトリのビルド結果）。ベータ版なのでトップページからはリンクしていません。

## 使い方

| パネル | やること |
| --- | --- |
| A. スクショ入力 | Ctrl+V で貼り付け、画面へドラッグ&ドロップ、またはクリックして選択（スマホはカメラロール）。認識した項目の枠が画像に重なります（緑=信頼度 高、黄=中、赤=低、灰の点線=組にならなかった文字）。うまく読めないときは「範囲を選んで読み直す」でパネル部分だけを囲む。スマホの文字認識でコピーしたテキストも「テキストで貼り付ける」から読めます。 |
| B. 確認フォーム | 読み取った値を枠ごとに確認・修正。行の左は元画像の切り抜き（ホバーで拡大）。項目名はプルダウンで付け替え可。辞書にない項目は「未分類」に並び、枠を割り当てるか「使う」を外して無視します。割り当てた内容は `labels.json` 用の JSON としてコピーできます。 |
| C. 追加入力 | 基礎攻撃力、属性相性、基礎 DA/TA、敵防御（10/15/20/任意）、特殊上限、パネル外のバフ（テンプレートから追加して枠を選ぶ）、奥義倍率、アビ倍率と減衰表。 |
| D. 結果 | 通常攻撃（1ヒット・1ターン期待値）、奥義、アビ。乱数による最小〜最大、計算の内訳（減衰前 → 減衰後 → 与ダメUP後 → 与ダメ上昇後）、各枠 +10% での伸び率、減衰グラフ（表表示あり）。 |
| E. キャリブレーション | パネルの予測ダメージ（防御10・通常攻撃1回・戦闘中バフなし）を正解に、順算・逆算・仮説フラグの全探索（7フラグ × 丸め3通り = 384通り）・複数スクショの一括探索。上位の仮定はワンクリックで通常の計算に適用できます。 |
| P. プリセット | 入力一式に名前を付けてこのブラウザに保存、2つ選んで結果を比較。ヘッダの「共有リンクをコピー」で入力一式を URL に入れて共有できます（スクショ画像は含みません）。 |

入力の単位は画面と同じです（54% は 54 と入力）。表示は3桁区切りで、表示するときだけ切り捨てます。

## 開発

```bash
cd damage-calc
npm install
npm run dev              # 開発サーバ（http://localhost:5173/）
npm test                 # 計算エンジン・パーサ・共有 URL の単体テスト（Vitest）
npm run test:ocr         # OCR のゴールデンテスト（Node 上の tesseract.js。遅い）
npm run report:calibration  # fixtures/panel-001.json で仮説探索のレポートを出力（合否判定なし）
npm run build            # 型チェック → ../damage/ に出力（サイトの /damage/ として配信）
```

- `npm run build` の出力 `../damage/` はリポジトリに含めます（サイトはビルド工程なしの静的配信のため）。ソースを変えたらビルドし直してコミットしてください。
- CDN を使わずに動かす（ローカル検証・自前ホスト）: `npm run tesseract:local` で `public/tesseract-local/`（34MB、git 管理外）に worker・core・言語データをコピーし、`VITE_TESS_BASE=./tesseract-local npm run dev`（またはビルド）。
- 画面の通し確認: 上の開発サーバを `VITE_TESS_BASE` 付きで起動して `npm run e2e`（Playwright。スクショを `.e2e-out/` に保存）。

### ディレクトリ

| パス | 中身 |
| --- | --- |
| `src/engine/` | 計算の純粋関数（React を import しない）。`types` `softcap` `defense` `attack`（枠・1ヒット・`calculate`）`postcap` `multiattack` `modifiers`（`panelToModifiers`）`calibrate` |
| `src/ocr/` | 前処理（`preprocess`: 拡大・max(R,G,B)・反転・大津の二値化）、行まとめと2列分割（`layout`）、辞書照合（`match`）、値のパース（`parse`）、`Recognizer` インターフェースと tesseract.js 実装（`tesseract`）、パイプライン（`pipeline`）、ブラウザ用の補助（`browser`） |
| `src/ui/` | 画面（React 18 + useReducer） |
| `data/` | 仕様上の定数。`softcaps.json`（減衰表・上限UPの上限・アビの追加減衰・特殊上限）、`frames.json`（攻撃力の枠）、`labels.json`（パネル項目辞書）、`formula.json`（乱数・防御の下限・予測ダメージの前提・クリティカル・減衰後の補正の順序） |
| `fixtures/` | テストの期待値。`panel-001.json` は手元のスクショの転記。`synthetic/` は CSS で描いた模擬パネル（`npm run fixtures:synthetic` で再生成）。手元のスクショ（`fixtures/*.png` など）は `.gitignore` 済み |

### データの直し方

数値や項目名はコードに直書きせず `data/*.json` に置いています。仕様変更や検証結果は JSON の修正（とビルド）だけで反映できます。

- 新しい項目名: `labels.json` の `labels` に追加（`slot` が計算での行き先。誤認識しやすい表記は `aliases` に足す）。確認フォームで未分類に枠を割り当てると、追記用の JSON をコピーできます。
- 新しい枠: `frames.json` に追加（`mode`: `additive` = 同じ枠は加算、`each` = 1つごとに乗算、`element` = 属性相性つき）。
- アビの減衰表のプリセット: `softcaps.json` の `skillPresets`（`thresholds` 4つ・`reductions` 5つ）。

## OCR の流れ

1. 短辺が 1200px 前後になるよう 1〜3 倍に拡大
2. 各画素の max(R,G,B) でグレースケール化（緑の予測ダメージ・オレンジの D上限 も明るく残る）→ 反転 → 大津の二値化。二値化あり / なしの2種類を認識し、単語の信頼度の合計が高い方を採用
3. tesseract.js（`jpn`、PSM 11 = 疎なテキスト）で全体を認識し、単語を y 座標で行にまとめる。「発動中の武器スキル」より下はグリッドの左右の中央で2つのセルに分ける
4. 各セルでラベルと値を組にする。カンマで分かれた数値（「847,」「974」）はつなぐ。値の読めなかったセルはラベルの右側だけを読み直す
5. 値の領域だけを切り出して `eng` + 文字ホワイトリスト（`0-9 . , % + -`）+ PSM 7 で読み直し、元より信頼度が高ければ置き換える（`jpn` とホワイトリストの組み合わせは空を返しやすいため、値の読み直しは `eng` の Worker を別に1つ作って使い回す）
6. NFKC 正規化と、OCR の信頼度で重み付けした正規化編集距離で辞書と照合。類似度 0.6 未満は未分類。候補が並んだときは値の単位・範囲が合う項目、まだ割り当てていない項目を優先する

確認フォームの信頼度は「OCR の単語信頼度」と「辞書照合の類似度」の小さい方です（高 ≥ 0.85、中 ≥ 0.6、低 < 0.6。`labels.json` の `confidenceLevels`）。

## テストの状況

- 計算エンジン（指示書 8.1）: 減衰（通常攻撃・上限UP・上限突破・奥義・アビの Olivia / Wilnas）、枠の乗算と枠内の加算、防御の差し引きと下限、連撃期待値はすべて通過。特殊上限（660万・1310万の段階的な減衰）とアビの追加減衰の倍率帯も gbf.wiki の数値でテスト。ほかにクリティカル・乱数平均・減衰後の補正の順序・特殊上限・上限UPの上限・伸び率・逆算・仮説探索・パーサ・共有 URL のテスト。
- OCR（`npm run test:ocr`）: 模擬パネル（1x / 2x）で 20/20 項目一致、ヘッダも一致。手元のスクショ `fixtures/panel-001.png` は置いたときだけ実行します（合格ライン 20 項目中 18 項目）。
- 画面（`npm run e2e`）: PC の Chromium でファイル選択・貼り付け・ドラッグ&ドロップ・結果・グラフのツールチップ・仮説探索・共有 URL・スマホ幅を確認。iPhone の Safari は未確認です。

### 手元のスクショでの仮説探索（参考）

`npm run report:calibration` の結果（`fixtures/panel-001.json`・`panel-002.json`）:

- どちらのパネルでも、対属性の誤差が最小になるのは「予測ダメージは減衰を含まない」仮説（1枚目 +0.29%、2枚目 +0.11%）。既定の仮定（減衰込み）では合わない
- 2枚目の無印/対属性の比 1.453 は、有利 +50% と属性攻撃 10% を同じ属性枠に足した値 (1.5+0.1)/(1+0.1) = 1.4545 とほぼ一致し、クリティカル・減衰を含まないことと合う
- 2枚目は主人公の攻撃力（編成画面 121,370）が分かっている。これを基礎攻撃力に入れると「パネル値は加護適用前（`panelValuesIncludeAura` OFF）・減衰なし・与ダメUPなし」で無印・対属性とも −2.1%（誤差がそろっているので、共通の係数が約 2% 足りない）。逆算した基礎攻撃力は 115,037（与ダメUPあり）。残りの差の原因は未解明
